#### TTS 입력 제한과 출력 스트리밍 — 2026-10-09

■ 기존 목표
설정한 모델로 음성을 만들고 입력·출력·취소와 캐시의 경계를 명확히 한다.

■ 수행 내용
텍스트를 UTF-8 64KiB와 수집 시간 130초로 제한하고, 출력 설정에 따라 완성 오디오 또는 지연 스트림을 반환한다. 종료 시 소유한 요청과 스트림을 정리한다.

■ 사용자 체감 변화
출력 스트리밍을 꺼도 입력 제한이 적용된다. 연결 설정을 바꾼 뒤 이전 연결에서 만든 음성이 재사용되지 않는다.

■ 수행 실패·미달성
실제 HA 전체 통합 자동 테스트와 공급자·스피커 인수 확인은 후속 단계다.

■ 주요 결정
호출별 모델 변경은 허용하지 않는다. 입력 지원과 출력 스트리밍 설정을 분리하며, 130초는 입력 수집 시간이고 입력 제공자의 종료 정리를 포함한 총시간은 아니다.

■ 테스트 방식·결과
TTS 관련 27개와 전체 단위 테스트 136개, 정적·서식 검사가 통과했다. 실제 HA 옵션 처리와 캐시 키 계산으로 오래된 옵션 재전달을 확인했다. 독립 4관점 검토의 잔여 지적은 없다.

■ QA 확인 방법
`python -m unittest discover -s tests -p 'test_tts*.py' -v`로 입력 한도·취소·지연 종료·옵션 격리를 재확인한다.

■ 부수 정정
HA가 엔티티 호출 전에 캐시를 반환하는 경로를 고려해, 연결마다 달라지는 옵션 이름도 캐시 식별에 포함했다.

■ 후속
실제 HA의 캐시·재설정·종료 동작을 자동 검증하고 사용자 안내와 CI를 갱신한다.

■ 산출물 위치

#### 실제 Home Assistant 자동 검증과 인수 준비 — 2026-10-09

■ 기존 목표
재설계한 STT·TTS가 실제 Home Assistant의 설정·등록·캐시·오디오 처리 계약을 지키는지 확인한다.

■ 수행 내용
설정·옵션 화면부터 등록, 다시 불러오기, 해제까지 실제 HA로 자동 검증한다. 다섯 공급자는 로컬 HTTP 서버로 응답하고 오디오는 FFmpeg로 디코딩한다. CI에 별도 HA 검사를 추가하고 영한 사용 안내를 갱신했다.

■ 사용자 체감 변화
설정 변경 후 오래된 음성 캐시를 재사용하지 않으며 입력 제한과 출력 스트리밍 동작을 안내에서 확인할 수 있다. 최소 지원 버전은 Home Assistant 2026.3.0이다. 기존 설치 경로와 엔티티 ID는 유지한다.

■ 수행 실패·미달성
실제 공급자 계정·모델, 기존 설치 업그레이드, Assist, 한국어·영어 음성 품질과 스피커 재생은 아직 검증하지 않았다. 공개·배포와 최종 통합은 대기한다.

■ 주요 결정
기존 Python 3.13 단위 검사를 유지하고 Python 3.14.2·HA 2026.3.0 검사를 분리했다. 자동 검증에서는 유료 요청을 하지 않는다. 실제 기기 확인 후 최종 통합한다.

■ 테스트 방식·결과
단위 테스트 150개와 실제 HA 테스트 46개가 모두 통과했고 건너뛴 테스트는 없다. 정적·서식·컴파일 검사와 네 관점의 누적 검토도 통과했다. HA와 외부 의존성에서 경고 51개가 발생했으며 테스트 실패는 없었다.

■ QA 확인 방법
README의 Development 명령으로 단위·실제 HA 검사를 각각 실행한다. 기존 설정과 ID 유지, 실제 Assist 전사, 한국어·영어 TTS, 출력 스트리밍 켜기·끄기, 재생 중 취소·재설정을 사용자 HA에서 확인한다.

■ 부수 정정
Gemini 전사 경로의 영한 설명을 바로잡고, 캐시 시험의 오디오 데이터가 다른 시험에 영향을 주지 않도록 분리했다.

■ 후속
실제 HA 인수 결과를 확인한 뒤 최종 통합 승인 절차를 진행한다. 자동 검사 통과를 실제 공급자·스피커 확인으로 대신하지 않는다.

■ 산출물 위치
`feature/VOICE-REDESIGN-1` 브랜치의 README, HACS 설정, CI와 `tests_ha/`. 재설계 계약은 `work/plans/VOICE-REDESIGN-1.md`에 있다.

■ 부수 정정

#### OpenRouter 모델별 요청 형식 설정 — 2026-10-09

■ 기존 목표
모델별 요청 포맷 차이를 코드 수정 없이 별도 설정 파일에서 관리한다.

■ 수행 내용
model_audio_formats.json에 기본 요청 형식 pcm과 minimax/speech-2.8-hd의 mp3 예외를 추가했다. 요청 형식은 지원 형식 목록에 포함되어야 하며 재생은 실제 응답 형식을 따른다.

■ 사용자 체감 변화
MiniMax Speech 2.8 HD에는 MP3를 요청하고 미등록 모델은 PCM을 요청한다. 파일 수정 뒤 통합 다시 로드 또는 HA 재시작으로 적용한다.

■ 수행 실패·미달성
수정 후 MiniMax 실제 재생 결과는 아직 확인하지 않았다.

■ 주요 결정
모든 모델을 나열하지 않고 정확한 모델 ID별 예외를 관리한다. PCM 샘플레이트·채널 수는 요청 형식 기본값과 별개이며 기존 응답 우선 처리를 유지한다.

■ 테스트 방식·결과
앞선 승인된 진단 1회에서 MiniMax의 OpenRouter 스트리밍 경로는 PCM 요청을 HTTP 400으로 거절하고 MP3를 요구했다. 이번 변경에는 테스트·추가 리뷰·공급자 호출을 수행하지 않았다.

■ QA 확인 방법
사용자의 실제 재생 관측을 기다린다. Mistral·Gemini는 앞 수정본에서 사용자가 재생 성공을 확인했다.

■ 부수 정정
MiniMax 자체의 모든 API가 PCM을 지원하지 않는다는 결론으로 확장하지 않는다.

■ 후속
전체 제품 종결은 대기한다.

■ 산출물 위치
feature/VOICE-REDESIGN-1의 audio_formats.py, client.py, model_audio_formats.json과 README. 변경 파일 3개를 기존 설치에 반영했다.


#### STT·TTS 재설계 통합 결과 — 2026-10-09

■ 기존 목표
기존 설치와 음성 기능을 유지하면서 설정·인증·공급자·HA 실행 경계를 전면 재설계하고, 관심사별 개발 이력과 설치 가능한 공개 릴리스를 제공한다.

■ 수행 내용
설정·인증 정책, 제한된 HTTP 전송, 공급자별 요청과 응답 수명, STT·TTS 엔티티를 분리했다. 서비스별 설정 화면과 실제 HA 회귀 검증을 연결하고 모델별 요청 형식 규칙을 별도 JSON으로 관리한다. 설치 안내·릴리스 노트·0.3.0 배포 ZIP을 준비했다.

■ 사용자 체감 변화
기존 통합 경로와 엔티티 ID를 유지하며 STT·TTS 또는 동시 사용을 설정할 수 있다. 서비스 순서는 OpenAI, Google Gemini, xAI, OpenRouter, OpenAI-compatible이며 커스텀 연결 입력은 호환 서버에서만 표시한다. OpenRouter 제미나이·미스트랄·MiniMax HD의 실제 재생을 확인했다.

■ 수행 실패·미달성
OpenAI·xAI는 API 키가 없어 실계정 재생을 확인하지 못했다. 모든 모델·기기·언어 조합을 검증한 결과가 아니다. GitHub 릴리스는 아직 공개하지 않았다.

■ 주요 결정
OpenRouter 요청은 기본 PCM, MiniMax Speech 2.8 HD는 MP3 예외를 적용한다. 실제 응답의 MP3·WAV는 그대로 전달하고 PCM은 응답의 샘플레이트·채널 수로 WAV를 구성한다. Gemini 전용 보완값은 두지 않는다. STT의 모델별 형식 분기는 필요성 조사에서 근거가 확인되지 않아 추가하지 않았다. 전체 문장을 받은 뒤 합성하며 출력 스트리밍은 선택 기능이다. OpenAI·xAI·호환 서버의 MP3 요청과 Google 전용 WAV/PCM 계약은 유지한다.

■ 테스트 방식·결과
단위 테스트 176개, HA 2026.3.0·2026.10.0 각각 88개 통합 테스트, Ruff check·format 58파일과 Python 컴파일 검사가 통과했다. HA 시험의 각 93개 경고는 외부 라이브러리 경고다. 정확성·아키텍처·보안·문서 검토와 배포 준비 검토를 수행했다. 자동 HTTP 계약 검증과 사용자가 확인한 OpenRouter 세 모델의 실제 재생은 구분한다. 배포 ZIP의 통합 파일 30개를 소스 바이트와 대조했다. 관심사별 7개 커밋은 전체 75파일을 누락·중복 없이 담으며, a23e7b10fe6a5bd1c4f6c3e8fef400969da40772의 원격 CI가 성공했다.
